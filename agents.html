Agents that work like teammates.

UAssist does not replace your judgment. It gives AI agents a safe, scoped way to do the parts of game development that can be verified by running them.

What agents are in UAssist

Agents are CLI tools installed on your machine. UAssist currently supports Claude Code and opencode. More adapters are coming. UAssist does not host the agent; it calls the binary you already have, in a directory it prepares, with a context packet it assembles.

The agent sees only what UAssist gives it. That includes the card description, the anchored file paths, related project conventions, and recent chat. It does not see your entire hard drive, your browser history, or unrelated projects.

The worktree model

When you dispatch a card, UAssist creates a git worktree named after the job. The agent edits inside that worktree. Your main working tree is untouched.

project/
  .git/
  Assets/               # your main tree, safe
  .uassist/
    worktrees/
      job-114/          # agent edits here
        Assets/Scripts/Player/PlayerShip.cs

When the agent finishes, UAssist computes a diff between the worktree and your base branch. You review the diff inside the card detail panel. If it looks right, you click Accept and the change merges in. If it does not, you click Reject and the worktree is discarded.

Clarity comes from separation. You cannot accidentally break the project because you never let the agent touch the project directly.

Tasks agents handle well

  • Code that compiles. C# scripts, shader stubs, JSON config, editor tooling.
  • Blender Python. Procedural models, batch export scripts, socket naming conventions.
  • Refactoring. Rename a field across several files, split a large class, move assets into folders.
  • Boilerplate. New MonoBehaviour stubs, new prefab wiring, repetitive inspector setup.
  • Tests and linting. Add validation logic, format code, fix warnings.

Tasks agents should not touch

  • Creative composition. Level layout, lighting feel, animation timing. A diff cannot tell you if it feels right.
  • High-stakes design decisions. Changing the core loop, the scoring model, or the art direction. These are human calls.
  • Anything you cannot verify quickly. If you cannot run it and see the result, do not dispatch it.
As DHH wrote, “The best way to build software is to start with something simple and iterate.” Agents excel at iterations once the direction is clear.

Unity and Blender in one job

A single card can have multiple anchors. A card called Build turret enemy can anchor to:

  • Assets/Scripts/Enemies/Turret.cs
  • Assets/Models/Enemies/Turret.blend
  • Assets/Prefabs/Enemies/Turret.prefab

The agent receives all three paths in its context. It can update the Blender model with named sockets, write the C# controller that rotates those sockets, and leave notes about what the prefab needs. After you accept the diff, you rescanned the workspace and the catalog catches up.

What goes into the context packet

UAssist builds the packet from stable project data:

  • The card title, description, and acceptance criteria.
  • Anchors: file paths, asset types, and whether they exist.
  • Project conventions you have saved from earlier jobs.
  • Recent chat messages on the card.
  • The output of relevant validators, if any.

The packet is editable before dispatch. If you want the agent to ignore a file or focus on a specific function, you change the packet. This is faster than rewriting the prompt from scratch.

Cost caps and timeouts

Every dispatch has a maximum cost in USD and a maximum duration in minutes. UAssist passes these to the adapter. If the agent runs long, it is stopped. If it burns through the budget, it is stopped. You are never surprised by a bill.
