Built for the messy middle

Game development is not a clean pipeline. It is a loop of decisions, experiments, and half-finished files. UAssist gives that loop a surface you can see and a record you can trust.

Plans become cards

Write your game plan in Markdown. Import it. UAssist turns phases into milestones, bullets into cards, and exit gates into acceptance criteria.

Tasks anchor to objects

A card about a weapon anchors to the Blender file, the prefab, and the C# script. Nothing floats in abstraction.

Agents stay isolated

Dispatch opencode, Claude Code, or any CLI agent. They run in their own git worktree. What comes back is a diff you review before accepting.

Health lane watches

Validators emit items for compile errors, missing references, licence gaps, and budget overruns. Click one and land on the exact asset.

Docs with memory

Write architecture notes in the Docs page and discuss them with the assistant. The chat is tied to the project, not to a browser tab.

Ship the game

Export knows your asset bundles and your licences. Credits are generated from the catalog, not reconstructed at the last minute.

Agents that work like teammates

UAssist talks to real CLI agents. Today that is Claude Code and opencode. More adapters will come. The agent does not live inside UAssist; it runs on your machine, sees only the context UAssist gives it, and returns a diff you can accept or reject.

Context is automatic

When you dispatch a card, UAssist builds a context packet: the card description, its anchors, related files, project conventions, and recent chat history. The agent starts with the same briefing you would give a collaborator. You do not paste code into a chat window and hope it remembers.

Worktrees keep you safe

Agents never write to your main working tree. UAssist creates an isolated git worktree for every job. The agent edits there. When it finishes, you see a unified diff. Accept it and the change merges in. Reject it and the worktree disappears. Your project never gets a surprise edit.

Agents touch the boring parts

Code is perfect for agents because you can verify it by running it. UAssist sends agents after scripts, shaders, JSON config, and small Blender Python tools. You keep the creative decisions: composition, feel, and whether the result is good enough.

Unity and Blender in one loop

A single card can anchor to both a Unity script path and a Blender file. The agent can update the C# controller and the model sockets in the same job. When it returns, you rescanned the workspace and both assets are catalogued. The boundary between the engines becomes just another file path.

Chat that knows the project

Every card and every doc page has its own chat thread. Ask about a card, ask the assistant to rewrite the description, or ask it to split a vague task into smaller ones. The chat uses the project state, not generic memory, and it can create new cards directly on the board.

Agents ask when unsure

If an agent hits an ambiguous requirement, it stops and asks instead of guessing. Your answer can be saved as a project convention. The next time a similar card comes up, the agent already knows the rule. Knowledge compounds.

The split is deliberate: agents write the verifiable parts, humans judge the result. That is how you move fast without losing control.

What it is not

UAssist does not replace Unity, Blender, or your IDE. It is a thin layer that keeps the work honest. It is local, plain-text, and fast enough to keep up with you.

It also does not pretend to plan for you. You write the plan. UAssist keeps it alive.
