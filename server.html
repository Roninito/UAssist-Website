One server per project.

UAssist is not a web app you log into. It is a local Bun process that serves the UI, the API, and the real-time event stream for one project root at a time.

A single process, three responsibilities

When you run bun run start, UAssist starts one Bun server. That process does everything:

  • REST API: cards, milestones, jobs, workspace, docs, and suggestions.
  • WebSocket: live board updates when anything changes.
  • Web UI: the board, detail panels, docs editor, and settings pages.

There is no separate frontend build step in development. Bun serves the TypeScript and HTML directly. When you ship, you can build a static bundle with bun run build:web.

The server follows the project root

UAssist state lives inside the target project, not inside the UAssist install directory. When you start the server from your game project:

cd /Projects/AsteroidRun
uassist serve

The server reads and writes the .uassist/ directory in that project. The JSON files there are the source of truth. The SQLite database is a cache.

Your projects are portable. Move the directory, clone it on another machine, or delete UAssist entirely. As long as you have the .uassist/ JSON files, you can rebuild everything.

Loopback by default

The server binds to 127.0.0.1:7373 by default. There is no authentication. The security model is that nobody outside your machine can reach it.

If you pass --unsafe-bind, it will bind to 0.0.0.0, but it warns loudly first. Do not use that unless you know what you are doing.

Port reclaiming

If 7373 is already taken, UAssist tries to identify the occupant. If it is another UAssist server for the same project, it stops the stale one and takes the port. If it is a different project or an unknown process, UAssist leaves it alone and picks the next free port in the range.

Sitting between engines

Unity and Blender do not know about each other. UAssist does. The server scans both workspaces, indexes assets by path and type, and exposes a single catalog to the web UI. A card can anchor to a Unity prefab and a Blender mesh at the same time because UAssist tracks both in one store.

It stays small on purpose

UAssist is not trying to become a platform. It is a local wrapper around your tools. One process, one project, one browser tab. That constraint is the feature. It keeps the tool honest.

The 37signals approach applies here: solve the problem with less. A dedicated server per project is less infrastructure, not more.
