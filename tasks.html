Tasks that stay tied to the work.

Every task in UAssist is a card. Cards have status, assignee, anchors, and acceptance criteria. The interface is designed so you always know what object a task is about.

The anatomy of a card

A card is more than a sticky note. It is a small contract with the following fields:

  • Title — short and specific enough to read on the board.
  • Description — the real requirement. Often written by the plan importer.
  • Status — open, active, blocked, review, or done.
  • Category — Systems, Gameplay, AI, UI, Audio, Art, Narrative, or Infra.
  • Assignee — human, agent, or unassigned.
  • Priority — normal or blocker.
  • Anchors — file paths, assets, or URLs the task touches.
  • Acceptance criteria — checkboxes that define “done.”

Anchors make tasks real

The most important field on a card is the anchor. An anchor ties the task to a concrete object in your project. Examples:

asset: Assets/Scripts/Player/PlayerShip.cs
asset: Assets/Models/Props/Crate.blend
asset: Assets/Prefabs/UI/HUD.prefab
web: design/progressions.md

When a workspace is linked, anchors show a badge: found if the path exists, or not in catalog if it has moved. This catches stale tasks before they become confusion.

If a task does not have an anchor, it is probably a wish. Anchors force you to name the thing the task changes.

Acceptance criteria

Each card can have a list of acceptance criteria. These are checkboxes. When they are all checked, the card is eligible for done. They are usually imported from plan exit gates:

- [ ] Ship can pitch, yaw, and throttle
- [ ] Boost drains a visible meter
- [ ] No compile errors in the Player folder

The criteria live in the JSON mirror, so they are versioned with the rest of the project.

The detail panel

Click any card on the board to open the detail panel. From there you can:

  • Edit the description and acceptance criteria.
  • Change status, assignee, or category.
  • Attach or remove anchors.
  • View linked cards and their blocking relationships.
  • Open the project chat thread for this card.
  • Dispatch an agent job.

Blocking and linking

Cards can block other cards. A card about the enemy base class blocks the cards for drones and turrets. Blocked cards are dimmed until their dependency moves forward. This keeps the board honest about what can actually be worked on.

A clear board is a clear project. If you cannot see the dependencies, you are planning with hope.
